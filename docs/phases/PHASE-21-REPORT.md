## 2. Backend Deliverables (`packages/calc`, `apps/api`, `tools`, `infra`)

- **Pure Notification Policy Engine (`packages/calc/src/notify/index.ts`, mirrored in `apps/api/src/modules/notifications/notify-calc.ts`):**
  - `decideChannels`, `isWithinQuietHours` / `nextQuietEndUtc` (IST quiet hours), `buildCollapseKey` (`<= 32` chars), `buildPayslipPassword` (`PAN[0..3] + DDMM` or `EMP_CODE + DDMM`), `renderEscapedTemplate`, and `findPiiVariablesInTemplate`.
- **NotificationService v2 (`apps/api/src/modules/notifications/service.ts`):**
  - Preserves Phase 5 `notify(tx, ...)` semantics inside caller transaction `tx` so rolled-back transactions emit zero DB rows and zero `pg_notify('erp_rt', ...)` signals.
  - Evaluates per-user channels, masks push bodies for `sensitive` types (`PAYROLL_PAYSLIP_RELEASED`), enforces `SECURITY` lock and mandatory `IN_APP` lock on `APPROVAL_ASSIGNED` while respecting user `PREF_OFF` on non-mandatory types, and exposes `seq` cursor pagination, `category` filtering, `markSeen`, `archiveNotification`, and Admin catalogue/settings management.
- **Multi-Process Real-Time SSE (`apps/api/src/modules/notifications/realtime.ts` & `infra/nginx/sawant-erp.conf`):**
  - `GET /api/v1/realtime/stream` backed by PostgreSQL `LISTEN erp_rt`, 25 s heartbeat comments, max 5 streams/user (closing oldest), `Last-Event-ID` 24-hour replay (up to 200 items, else `resync`), and Nginx SSE proxy buffering disabled on `/sawant-erp/api/v1/realtime/`.
- **Web Push (`apps/api/src/modules/notifications/push-service.ts`, `tools/gen-vapid.ts`):**
  - Classic + Apple Declarative Web Push payloads (`<= 2048` bytes), `404/410` auto-revocation (`GONE_410`), `413` body-trim retry, `429 Retry-After` backoff, 60-day idle revocation (`push.cleanup`), and automatic revocation on `logoutAll` (`auth/service.ts`) and user deactivation (`users/service.ts`).
- **Admin Broadcasts (`apps/api/src/modules/notifications/broadcast-service.ts`):**
  - Live audience preview by all/unit/department/role/user (active users only), `Director+` approval workflow (creator != approver) when recipients > 50 or `EMAIL`/`SMS` or `CRITICAL`, Administrator/Super User `Emergency` bypass audited with mandatory reason, 500-user batch delivery, `Withdraw`, `Cancel`, per-unit reporting, pinned banners, and blocking `require_ack` acknowledgements.
- **Email Automation & SES Webhook (`apps/api/src/modules/notifications/email-automation-service.ts`):**
  - Idempotent rule dispatch (`sales_invoice.posted`, `payroll.payslip.released`, manual `/documents/:docType/:id/email`), stored-PDF reuse + `<= 7 MB` attach vs 30-day `dms_share_links` cutoff, AES-256 encrypted payslip PDF (`body_stored = false`, format-only instructions), raw MIME via AWS SES v2 (`@aws-sdk/client-sesv2`) with SMTP fallback, `/comm/messages/:id/resend` with mandatory reason, and SNS-signed `POST /api/v1/webhooks/inbound/ses` handling bounces, suppressions, owner alerts, and 0.3% marketing auto-pause.
